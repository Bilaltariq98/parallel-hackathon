# Company Planets — verified inspiration and code donors

Research snapshot: **11 November 2026**. **25 candidate techniques across 21 repositories**: five ranked picks, followed by 20 alternatives. Official three.js examples share the parent repository's stars and commit date; these are not separate project popularity counts.

**Decision:** ship a small WebGL scene with procedural sphere shaders, restrained monochrome rendering, and CPU gravity. The spectacular GPU fluid, SDF and terrain engines below are useful references, but adopting one wholesale would jeopardize the under-one-hour build.

## Verification and how to read this

I used `gh search repos`, `gh search code`, web search, GitHub repository/README/licence/tree/commit APIs, and direct source reads. Every listed repository was opened through GitHub's API, its README read where present, and at least one implementation file skimmed. Planet-3D has **no README**; its substantial in-app `src/help.md` was read instead. Source links below pin the inspected commit unless an explicitly named three.js release is more useful.

Stars and commit dates are live GitHub observations, not search snippets. “Last commit” means the default branch's HEAD committer date, not the last edit to a particular shader. Versions are declared package ranges or the vendored `REVISION`, not an inferred compatibility guarantee. Demo HTTP checks verify that a page responds, **not that WebGL executes, all assets load, or 60 fps is sustained**. No project was installed, built, or benchmarked.

Estimates are engineering judgments for an experienced three.js developer lifting the named piece into an existing vanilla scene. They exclude research API setup, unfamiliar-toolchain debugging and full-app ports. They are **alternatives, not five tasks that all fit into an hour**. “No build” still means serving ES modules over HTTP(S); it does not mean double-clicking a `file://` page.

The [three.js forum planet showcase](https://discourse.threejs.org/t/procedural-planet-generator/59244) led to pick 1 and independently flags its rotated-lighting issue. The [official examples index](https://threejs.org/examples/) was checked, then the individual source examples below were inspected.

## Ranked shortlist — five best things to use tonight

### 1. [dgreenheck/threejs-procedural-planets](https://github.com/dgreenheck/threejs-procedural-planets) — the planet core

- **Take:** the `noise-functions`, `planet-vert-shader` and `planet-frag-shader` blocks in [index.html](https://github.com/dgreenheck/threejs-procedural-planets/blob/23457d4f8e6bedf22aa266e12c92f850822ff3a4/index.html); uniform wiring in [scripts/main.js](https://github.com/dgreenheck/threejs-procedural-planets/blob/23457d4f8e6bedf22aa266e12c92f850822ff3a4/scripts/main.js). Displaced sphere, terrain-height colour bands, ocean-like specular regions and tunable noise already fit fact-driven traits.
- **Verified:** 303 stars; latest default-branch commit [2025-02-03](https://github.com/dgreenheck/threejs-procedural-planets/commit/23457d4f8e6bedf22aa266e12c92f850822ff3a4); [MIT](https://github.com/dgreenheck/threejs-procedural-planets/blob/23457d4f8e6bedf22aa266e12c92f850822ff3a4/LICENSE); three **^0.159.0** in [package.json](https://github.com/dgreenheck/threejs-procedural-planets/blob/23457d4f8e6bedf22aa266e12c92f850822ff3a4/package.json); vanilla JS with Vite, no React; [demo](https://dgreenheck.github.io/threejs-procedural-planets/) HTTP 200.
- **Lift: 15–25 minutes** for the terrain material on one pinned three.js version, with simplified lighting. Replace Vite/bare imports with a local import map, add missing `.js` suffixes, and omit the GUI, skybox, bloom and particle-cloud system.
- **Required adaptation:** it has no explicit seed uniform. Hash the normalized domain into a fixed `vec3` offset and apply it to *every* terrain-noise sample, including bump samples. Colours/thresholds are direct fact controls. The original shader mixes local surface coordinates with world-space camera/light inputs: transform consistently before translating/rotating planets. Clamp the specular dot product before `pow`.
- **Performance:** default 128×128 sphere, 10 noise octaves and three terrain evaluations per fragment are excessive for a room full of planets. Start at 48×32 and 3–4 octaves; remove bump recomputation if needed. [scripts/atmosphere.js](https://github.com/dgreenheck/threejs-procedural-planets/blob/23457d4f8e6bedf22aa266e12c92f850822ff3a4/scripts/atmosphere.js) uses 4,000 transparent points and `Math.random()`; it is neither a cheap shell nor seeded. Its cloud/sky images total only about 21 KB, so overdraw is the larger concern. Preserve the Ashima noise attribution as well as the project MIT notice.

### 2. [mrdoob/three.js](https://github.com/mrdoob/three.js) — drag, release and camera control

- **Take:** [DragControls.js](https://github.com/mrdoob/three.js/blob/r159/examples/jsm/controls/DragControls.js) and the wiring in [misc_controls_drag.html](https://github.com/mrdoob/three.js/blob/r159/examples/misc_controls_drag.html). The ray/plane projection and `dragstart` / `drag` / `dragend` events remove most input plumbing.
- **Verified:** 118,171 stars; latest default-branch commit [2026-11-11](https://github.com/mrdoob/three.js/commit/054a1fa19be93fc4f729f89dd12438b55b96aeaa); [MIT](https://github.com/mrdoob/three.js/blob/054a1fa19be93fc4f729f89dd12438b55b96aeaa/LICENSE); inspected current package **0.187.0 on dev**, but **use the separately inspected r159 files with the r159 planet core**. r159 resolves to commit `09fe0527` dated 2023-11-30. No framework or build needed with local ESM/addons; [demo](https://threejs.org/examples/misc_controls_drag.html) HTTP 200.
- **Lift: 5–10 minutes** for dragging; **10–15 minutes** including release velocity and conflict handling with orbit controls. Fling is an addition: retain recent world-space drag samples, derive/clamp velocity on release, pause physics for the held body, then resume.
- **Trap:** shader-displaced planets still have the CPU geometry's original picking surface. Use an invisible sphere proxy with the actual planet radius, or intersect an analytic sphere. Rings/cloud children should not steal selection. Do not mix current-dev addons with r159 core. No large assets are needed for this extraction.

### 3. [paradoxxxzero/annealation](https://github.com/paradoxxxzero/annealation) — gravity and merging

- **Take:** `compute3` in [src/gravity/p2p.js](https://github.com/paradoxxxzero/annealation/blob/3c2212fa8fe39387f7b3be916aaf6857acaa66bb/src/gravity/p2p.js) and the momentum-weighted merge idea in `solveCollisions` in [src/gravity/gravity.js](https://github.com/paradoxxxzero/annealation/blob/3c2212fa8fe39387f7b3be916aaf6857acaa66bb/src/gravity/gravity.js). It is an ambitious 2D/3D/4D simulator with JS, worker and Rust/Wasm implementations; only the small 3D equations are useful tonight.
- **Verified:** 46 stars; latest default-branch commit [2024-11-22](https://github.com/paradoxxxzero/annealation/commit/3c2212fa8fe39387f7b3be916aaf6857acaa66bb); [MIT](https://github.com/paradoxxxzero/annealation/blob/3c2212fa8fe39387f7b3be916aaf6857acaa66bb/LICENSE); three **^0.168.0**, Vite and optional wasm-pack/Rust in [package.json](https://github.com/paradoxxxzero/annealation/blob/3c2212fa8fe39387f7b3be916aaf6857acaa66bb/package.json); [demo](https://paradoxxxzero.github.io/annealation/) HTTP 200, redirecting to the author's current domain.
- **Lift: 10–20 minutes** for a stripped CPU force/merge loop; **1–3 hours** for the full multi-backend application. The force math itself is independent of three.js version.
- **Required adaptation:** use `compute3` even if gameplay is constrained to a plane; its `compute2` implements a different distance law. Replace the shared collision threshold with each pair's summed radii. Process each pair once and remove merged bodies safely; do not transplant the whole collision aggregation machinery. Use a fixed step and softening. Decorative debris should not join the gravity solver.

### 4. [emilwidlund/ASCII](https://github.com/emilwidlund/ASCII) — the shortest GPU ASCII route

- **Take:** [src/index.ts](https://github.com/emilwidlund/ASCII/blob/e0ef82c08610aeaa2c6fd06fd242bdc10fd25951/src/index.ts): the glyph-atlas creation and fragment shader sampling one scene colour per character cell. Canvas draws the atlas once; the frame conversion runs on the GPU.
- **Verified:** 214 stars; latest default-branch commit [2024-08-19](https://github.com/emilwidlund/ASCII/commit/e0ef82c08610aeaa2c6fd06fd242bdc10fd25951); **MIT declared in [package.json](https://github.com/emilwidlund/ASCII/blob/e0ef82c08610aeaa2c6fd06fd242bdc10fd25951/package.json)**, but no standalone LICENSE file; three **^0.151.3**, `postprocessing` **6.30.2**, TypeScript compiler. README shows React usage, but the effect is not inherently React-dependent. **No standalone live demo URL found in the README or repository homepage.**
- **Lift: 10–20 minutes**. Strip TypeScript and adapt `mainImage(inputColor, uv, outputColor)` to a vanilla `ShaderPass` with explicit `tDiffuse` and `resolution`, avoiding a second composer library. Use nearest filtering and a short glyph ramp.
- **Tradeoff:** coarse glyphs can erase moons, city lights and small rings. Keep text labels as crisp HTML, enlarge cells only after testing projector legibility, and retain a plain-render toggle. Package-only MIT is stated permission, but provenance is less complete than a checked-in licence text; preserve the declaration/author attribution if extracting. An explicit-licence alternative is the morphing toolkit below, at greater integration cost.

### 5. [richard-green/planetoid-generator](https://github.com/richard-green/planetoid-generator) — rings, storms and richer planet variants

- **Take first:** [RingShaders.ts](https://github.com/richard-green/planetoid-generator/blob/1cd8ac049bcd1a8d5cf12082bf01f6e267898d51/src/lib/components/Threlte/Rings/RingShaders.ts) and uniform/material setup in [Rings.svelte](https://github.com/richard-green/planetoid-generator/blob/1cd8ac049bcd1a8d5cf12082bf01f6e267898d51/src/lib/components/Threlte/Rings/Rings.svelte). Procedural band widths, seeded grain and planet shadowing are highly visible fact cues.
- **Verified:** 0 stars; latest default-branch commit [2026-11-01](https://github.com/richard-green/planetoid-generator/commit/1cd8ac049bcd1a8d5cf12082bf01f6e267898d51); [MIT](https://github.com/richard-green/planetoid-generator/blob/1cd8ac049bcd1a8d5cf12082bf01f6e267898d51/LICENSE); three **^0.185.1**, Svelte 5 + Threlte + TypeScript + Vite in [package.json](https://github.com/richard-green/planetoid-generator/blob/1cd8ac049bcd1a8d5cf12082bf01f6e267898d51/package.json); [demo](https://rdgreen.dev/planetoids/) HTTP 200. Low stars do not negate the inspected implementation.
- **Lift: 15–30 minutes for rings alone**, **45–90 minutes** for the gas-giant material/texture pipeline, several hours for the full editor. Exported GLSL strings are separable from Svelte; recreate the uniforms and a `RingGeometry` with double-sided transparency.
- **Stretch:** [GasGiantShaders.ts](https://github.com/richard-green/planetoid-generator/blob/1cd8ac049bcd1a8d5cf12082bf01f6e267898d51/src/lib/components/Threlte/GasGiant/GasGiantShaders.ts) contains seeded bands and `stormField`; [AtmosphereShaders.ts](https://github.com/richard-green/planetoid-generator/blob/1cd8ac049bcd1a8d5cf12082bf01f6e267898d51/src/lib/components/Threlte/Atmosphere/AtmosphereShaders.ts) contains an eight-sample atmosphere integration.
- **Trap:** the ring shader is not a tiny free effect: loops over bands plus fractal grain add pixel cost. Use fewer bands or plain concentric geometry tonight. The gas-giant shader is a full-screen texture-generation pass, not a drop-in sphere fragment shader. Keep the whole application out of the no-build scaffold.

## Recommended stack

**Baseline:** locally vendor **three.js 0.159.0** and matching ESM addons, use `WebGLRenderer`, an import map and a plain HTTP-served page. This is a deliberate compatibility pin to the leading planet donor, not a claim that r159 is current. The inspected upstream dev package is 0.187.0. Choose one revision and keep every addon on it; do not bring r182+ raymarcher/TSL components into the same build.

**Planet:** use pick 1's height-based sphere shader with three or four noise octaves and a domain-derived seed offset. Share geometry and the shader program, with separate per-company uniforms. Ocean coverage and terrain contrast should read in silhouette/large colour bands. Add a cheap shell from tiny-planets only if needed. For rings use simple concentric RingGeometry bands first; pick 5 is the upgrade. For city lights borrow the official Earth example's night mask, replacing the photographic map with sparse, seeded dots constrained to land. This city generator is new work, not an existing feature claimed for the shortlisted donor. For a storm, one rotating band/patch reads better on a projector than a full fluid simulation.

**Look:** black background, off-white planet tones, one accent for selection, trajectory and fresh impacts. Start with a small independently written 4×4 Bayer pass or just quantized lighting plus monospace HTML labels. This avoids the unresolved upstream provenance in the dithering repo. If actual ASCII is essential, use pick 4's atlas approach in a single fullscreen ShaderPass; it is an alternative to dithering, not another stacked pass. Keep labels outside post-processing. Film grain/CRT distortion/bloom are optional and usually reduce distant-room legibility.

**Play:** a central attractor and up to roughly 24 company bodies on a shallow orbital plane, rendered in 3D. Start with tangential velocities, then use softened Newtonian acceleration from Annealation's `compute3`, fixed-step integration, and sphere-overlap merges. At this scale a simple CPU loop is easier to inspect and associate with company metadata than GPU state. DragControls gives held-body motion; recent drag samples provide release velocity. Pause orbit controls while dragging. On collision, preserve total mass and mass-weighted velocity, grow the survivor toward a volume-combined radius, and emit 32–128 short-lived Points particles with ballistic motion. This debris effect is a proposed small addition, not a claim that Annealation ships it.

**Animation and budget:** animate planet arrival with scale/uniform interpolation; damp camera focus toward the selected planet and its orbit target. Use time-based updates, cap catch-up work after tab inactivity, and avoid compiling a different shader for each fact combination. Start at pixel ratio 1, bounded internal resolution, no shadows, no HDR skybox and no bloom. A 60 fps requirement is a 16.7 ms frame budget; measure on the actual laptop/projector. If it misses, reduce resolution, then bump-noise work, then cloud transparency before removing interaction.

**A realistic 45–55 minute target**, assuming the research API/proxy is already callable: 15–20 min basic planets and stable seeding; 10–15 min drag/gravity/merge; 10 min URL → facts → uniforms; 5 min monochrome treatment; 5 min projector check and tuning. Full ASCII, elaborate rings and procedural cities are substitutes/stretch goals, not all included in that estimate. Keep a playable sphere-and-fling loop by minute 25. API authentication/proxy setup, networking for multiple devices or chasing build incompatibilities can invalidate the time budget.

Keep the domain seed stable while facts arrive. Represent an unresolved fact as unknown rather than silently false. Map the ~20 flags into a few readable channels—water fraction, surface roughness, ring presence/bands, moons, night lights and storm activity—and ease those values when a completed result arrives. Seed decorative details separately so repeated renders do not reshuffle terrain.

## Rejected for tonight / do not re-check

- **fullofstars and galaxy-sim code:** no stated project licence; inspiration only despite reachable demos.
- **ProceduralTerrains full studio:** excellent LOD engineering, but many shader subsystems, framework setup and large optional texture assets.
- **ProceduralEarth full renderer:** r86-era generated shader archive, atmosphere/LUT and HDR pipeline; too much integration for the slot.
- **prolearner and holgerl full generators:** static HTML is attractive, but r82dev/r68 code is not modern-drop-in; migration is untested and over budget.
- **colordodge whole app:** r85-era Webpack/glslify/Wagner and multi-pass map generation; use as visual reference.
- **Planet-3D whole app:** raw WebGL/Browserify renderer migration; keep only bake-once/gradient ideas.
- **jsOrrery whole app:** ephemerides and real physical units solve a different problem; its force helper is the useful part.
- **official Canvas/DOM AsciiEffect as default:** per-frame pixel readback and HTML generation are a worse fit for the stated frame budget than a GPU glyph atlas.
- **dithering-shader as an unquestioned copy donor:** repo MIT is verified, but its credited Shadertoy source licence was not accessible; independently implement Bayer math instead.
- **morphing ASCII full stack:** useful next iteration; distance fields, temporal memory and multiple effect controls cost integration/tuning time.
- **Flow / WebGPU-Ocean / TSL compute as core gameplay:** compute support on the presentation machine is unknown, and they require a different rendering/simulation setup.
- **three-raymarcher + Ammo as the base:** current three >=0.182, indirect-lighting assumptions, Wasm and raymarch cost; use the smooth-merge idea.
- **full GPGPU protoplanet solver:** attractive accretion, but quadratic GPU force work and inaccessible per-company state complicate picking and labels.
- **Phone multiplayer, infinite zoom, audio-reactivity:** defer as feature scope. No phone-controller repository was sufficiently verified in this pass; none is presented as a vetted recommendation.

No selected code donor was found to declare GPL or a non-commercial licence. That does **not** establish rights to every bundled image, music file or upstream shader. Preserve the specific notices for copied code. Package-only declarations (ASCII/MIT, ProceduralPlanet/WTFPL, planet-3d/Unlicense) are explicitly distinguished from missing licences.
